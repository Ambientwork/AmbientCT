# Lightweight test-only dependency set for the Docker `test` build stage
# (plan §9 P2.1's explicit escape hatch: "darf der Agent für reine Unit-
# Tests einen zweiten leichten Requirements-Satz verwenden").
#
# Why this file exists (not just requirements.txt + requirements-dev.txt):
# requirements.txt pins numpy==2.2.0 for nnunetv2==2.5.1, but
# pydicom-seg==0.4.1 requires numpy<2.0.0 — pip (and uv) both report this
# as an unresolvable conflict when torch/torchvision/nnunetv2 and
# pydicom-seg are installed together. This conflict pre-exists in
# requirements.txt (not introduced by this phase) and is NOT fixed here:
# requirements.txt's "do NOT downgrade" numpy pin is an explicit prior
# decision for real nnU-Net inference correctness, out of scope for the
# test harness.
#
# This is safe because the unit test suite (ai-inference/tests/) never
# imports torch, torchvision, or nnunetv2 at collection time — verified by
# grepping pipeline/*.py: both `import torch` and the nnU-Net predictor
# import live inside pipeline/segmentation.py function bodies (lazy,
# real-inference-only code paths), not at module scope. No current test
# exercises those paths (see the `real_model` marker in pytest.ini for the
# category reserved for when they are).
#
# Consequence: this test stage does NOT install and does NOT exercise
# torch/nnunetv2/real inference. It must never be reported as a passed
# real-model or real-inference validation — only as what it is: the
# reproducible unit-test environment for demo-mode / mocked-predictor
# code paths.
#
# numpy left unpinned (any pin here would just re-create the same
# conflict) — pip resolves it to a <2.0 release that satisfies
# pydicom-seg==0.4.1.
